2.1 Process, Process States & PCB

Program passive instructions ka set hai; process us program ka execution instance hai. Process execution ke dauran state change karta hai.

New → Ready → Running → Waiting/Blocked → Ready → Running → Terminated
  • New: process create ho raha hai.
  • Ready: CPU ke liye wait kar raha hai.
  • Running: instructions execute ho rahi hain.
  • Waiting/Blocked: I/O ya kisi event ka wait.
  • Terminated: execution complete.

PCB (Process Control Block) OS ka per-process record hai. Ismein process state, program counter, CPU registers, scheduling information, memory-management information, accounting information aur I/O status jaisi details rakhi ja sakti hain. Context switch ke time PCB critical hota hai kyunki old process ki execution information save karke new process ki information restore ki ja sakti hai.

2.2 Process Scheduling: Queues, Schedulers & Context Switch

Processes different queues mein ho sakte hain. Ready queue CPU ke liye ready processes rakhti hai; device/I/O queues waiting processes ko represent karti hain.

  • Long-term scheduler: jobs ko system mein admit karne ke decision se associated.
  • Short-term scheduler: ready processes mein se CPU ke liye next process select karta hai.
  • Medium-term scheduler: memory pressure ya scheduling policy ke context mein processes ko temporarily suspend/resume karne se associated.

Context switch mein current process ka CPU context save aur selected process ka context restore hota hai. Ye useful hai, lekin switch ke dauran CPU application instructions execute nahi kar raha hota, isliye excessive context switching overhead create kar sakti hai.

2.3 Inter-Process Communication (IPC)

Shared Memory

Do ya zyada processes ek common memory region share karte hain. Data exchange fast ho sakta hai, lekin concurrent access ko synchronization ki zarurat hoti hai.

Message Passing

Processes send/receive operations ke through messages exchange karte hain. Shared address space ki direct requirement kam hoti hai; distributed systems mein concept naturally useful hai.

Exam point: IPC ka purpose process cooperation aur data exchange hai. Shared memory mein synchronization important hai; message passing mein communication primitives important hain.

2.4 Threads & Multithreading Models

Thread process ke andar execution ka lightweight unit hai. Threads same process ke resources share kar sakte hain, jabki har thread ke paas apna execution state jaise program counter aur registers hote hain. Benefits: responsiveness, resource sharing, economy aur multicore systems par parallelism.

ModelMappingCore idea
Many-to-OneMany user threads → one kernel threadSimple mapping, but one blocking operation/limited parallelism can affect the process.
One-to-OneOne user thread → one kernel threadBetter concurrency; kernel-thread creation overhead may increase.
Many-to-ManyMany user threads → pool of kernel threadsFlexible mapping; implementation is more complex.
