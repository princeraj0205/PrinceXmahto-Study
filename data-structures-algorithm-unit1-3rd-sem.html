1.1 Data Types

Data type batata hai ki data kis nature ka hai aur us data par kis type ke operations perform kiye ja sakte hain. Data structures padhte waqt data types ko samajhna important hai kyunki structure ke andar hum kisi type ka data store karte hain.

System-defined data types

System-defined ya built-in data types programming language/system ke dwara provide kiye jaate hain. C jaise language mein common examples int, char, float, double hain.

Data TypeTypical use
IntegerWhole numbers
CharacterSingle character
FloatDecimal/real values
DoubleHigher-precision real values

User-defined data types

User-defined data type programmer apni requirement ke according create karta hai. Data Structures ke context mein structure/record, class jaise constructs ka use related data ko organize karne ke liye kiya ja sakta hai.

Simple idea: Agar student ke paas roll number, name aur marks jaise related fields hain, to unhe ek user-defined record/structure ke andar organize kiya ja sakta hai.

1.2 Basic Concept of Data Structure

Data Structure data ko organize aur store karne ka ek systematic way hai, jisse data ko efficiently access aur manipulate kiya ja sake.

Data→Organize→Store→Access / Manipulate

Official course rationale bhi data structures ko data ko efficiently organize/store karne ke ways ke roop mein describe karta hai, aur suitable data structure choose karne se algorithm ki performance optimize ho sakti hai. fileciteturn61file3

Linear Data Structure

Linear data structure mein elements ek logical sequence/line mein arranged hote hain. Ek element ke baad next element ka relation clear hota hai.

Examples: Array, Linked List, Stack, Queue.

Non-linear Data Structure

Non-linear structure mein data simple single sequence mein arrange nahi hota. Elements ke beech hierarchical ya network-type relationships ho sakte hain.

Examples: Tree aur Graph.

LinearNon-linear
Sequential organizationHierarchical/network organization
Array, Linked List, Stack, QueueTree, Graph

Abstract Data Type (ADT)

ADT data aur uske allowed operations ka logical specification hai. ADT ye batata hai ki data structure kya operations support karega; implementation ka exact internal method alag ho sakta hai.

Example — Stack ADT: Stack mein push, pop aur peek jaise operations define kiye ja sakte hain. Stack ko array ya linked list se implement kiya ja sakta hai.
Exam line: ADT implementation details hide karke data aur operations ka logical view provide karta hai.

1.3 Algorithm and its Analysis

Algorithm kisi problem ko solve karne ke liye finite, ordered aur clear steps ka sequence hota hai.

Good algorithm ki basic characteristics

  • Input: zero ya more inputs ho sakte hain.
  • Output: kam se kam ek meaningful result expected hota hai.
  • Definiteness: har step clear aur unambiguous hona chahiye.
  • Finiteness: algorithm finite steps ke baad terminate hona chahiye.
  • Effectiveness: steps practically executable hone chahiye.

Example: Array mein maximum element

Algorithm:
1. First element ko maximum maan lo.
2. Har next element ko maximum se compare karo.
3. Agar current element bada hai, maximum update karo.
4. End mein maximum return/print karo.

Algorithm analysis ka purpose ye samajhna hai ki input size badhne par algorithm ke resources ka behaviour kaisa hoga.

Time Complexity aur Space Complexity

Time Complexity

Time complexity batati hai ki input size n ke badhne par algorithm ka running work kaise grow karta hai. Ye normally exact seconds nahi batati; hum operations ki growth ko analyse karte hain.

PatternTypical complexityIdea
Single loopO(n)n times work
Two nested loopsO(n²)n × n work
Three nested loopsO(n³)n × n × n work
Halving search spaceO(log n)Problem repeatedly half hota hai

Example — O(n)

for i in range(n):
    print(i)

Loop approximately n times execute hota hai, isliye growth O(n) hai.

Example — O(n²)

for i in range(n):
    for j in range(n):
        print(i, j)

Outer loop n times aur inner loop har baar n times, total approximately n² operations.

Space Complexity

Space complexity algorithm ko execution ke time required memory/resources ki growth ko describe karti hai. Ismein input storage aur algorithm ke extra memory usage ka context consider kiya ja sakta hai; syllabus ka focus algorithm analysis mein space complexity par hai.

Simple example: Agar algorithm input ke alawa sirf kuch fixed variables use karta hai, auxiliary space constant ho sakta hai. Agar n elements ka extra array banata hai, extra space O(n) ho sakti hai.

Best Case, Worst Case aur Average Case

Same algorithm ke running work ka behaviour different inputs par different ho sakta hai. Isliye three common cases analyse kiye jaate hain.

CaseMeaningExample idea: Linear Search
Best caseSabse favourable input.Element first position par mil jaye.
Worst caseSabse unfavourable input.Element last mein ho ya absent ho.
Average caseTypical/expected inputs ke according running work.Element generally middle/various positions par mil sakta hai.
Remember: Best = favourable situation, Worst = maximum work situation, Average = expected/typical behaviour.

1.4 Asymptotic Notation

Asymptotic notation ka use algorithm ki growth ko input size ke respect mein describe karne ke liye kiya jata hai. SBTE Unit 1 mein specifically Big-O, Omega (Ω) aur Theta listed hain. fileciteturn61file0

Big-O — O()

Big-O commonly algorithm ki upper-bound / growth limit describe karne ke liye use hota hai.

f(n) = 3n + 5

Growth ke liye dominant term n hai
⇒ O(n)

Constants aur lower-order terms ko asymptotic growth mein ignore kiya jata hai.

Omega — Ω()

Omega notation algorithm ki lower-bound growth ko describe karti hai.

f(n) = 3n + 5
⇒ Ω(n)

Theta — Θ()

Theta notation tight asymptotic bound describe karti hai jab function ki growth same order ki upper aur lower bound dono se represent ho.

f(n) = 3n + 5
⇒ Θ(n)
NotationBasic idea
O(g(n))Upper bound / growth ceiling
Ω(g(n))Lower bound / growth floor
Θ(g(n))Tight bound / same asymptotic order

Common growth order

Generally small growth faster hoti hai as input becomes large:

O(1)  <  O(log n)  <  O(n)  <  O(n log n)  <  O(n²)  <  O(n³)  <  O(2ⁿ)
Exam caution: Is list ko exact performance seconds ki list mat samjho. Ye asymptotic growth rates ko compare karne ka simplified order hai.

1.5 Time Complexity of Recursive Algorithm

Recursion mein ek function/algorithm apne aap ko smaller input/problem ke saath call karta hai.

Recursion ke two important parts

  • Base case: condition jahan recursion stop hoti hai.
  • Recursive case: function smaller/subproblem ke liye khud ko call karta hai.
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)

Yahan n == 0 base case hai aur factorial(n - 1) recursive call hai.

Recursive algorithm ki complexity kaise sochte hain?

Recursive code ko analyse karte waqt dekho: ek call kitne recursive calls generate karta hai, problem size kitna reduce hota hai, aur har call ka extra work kitna hai.

PatternTypical recurrence/ideaCommon growth
One call, n → n-1T(n)=T(n-1)+O(1)O(n)
Two calls, n → n-1T(n)=2T(n-1)+O(1)O(2ⁿ)
One call, n → n/2T(n)=T(n/2)+O(1)O(log n)

Master Theorem

Master Theorem divide-and-conquer type recursive recurrences ko analyse karne ke liye use hota hai. General form ko commonly:

T(n) = aT(n/b) + f(n)

ke form mein represent kiya jata hai, jahan a recursive subproblems ki count, n/b har subproblem ka size aur f(n) recursion ke bahar ka work represent karta hai.

Exam-level approach

  1. a, b aur f(n) identify karo.
  2. n^(log_b a) calculate/compare karo.
  3. f(n) ki growth se comparison karo.
  4. Applicable Master Theorem case se final asymptotic complexity obtain karo.
Example: T(n)=2T(n/2)+n mein a=2, b=2 aur f(n)=n. Yahan n^(log₂2)=n, so recursive-tree contribution aur f(n) same order ke hain; resulting complexity Θ(n log n) hoti hai.
Important: SBTE syllabus mein Master theorem explicitly Unit 1.5 ka part hai, isliye recurrence identify karna aur standard cases ka application exam ke liye practice karo. fileciteturn61file1

Practical 1 — Find size of different data types

#include <stdio.h>

int main() {
    printf("int = %zu bytes\n", sizeof(int));
    printf("char = %zu bytes\n", sizeof(char));
    printf("float = %zu bytes\n", sizeof(float));
